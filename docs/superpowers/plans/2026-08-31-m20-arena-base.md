# M20 Arena Base Implementation Plan

> **For Codex:** Execute this plan with `superpowers:executing-plans`, preserving strict test-first cycles and the manual-review boundary.

**Goal:** Deliver the documented M20 Arena base: independent White/Black engine configurations and isolated hosts, authoritative engine-v-engine clocks and game progression, bounded Arena opening setup, canonical Arena persistence, and an evaluation bar enabled by default.

**Architecture:** Reuse the single serialized `game-runtime` owner with both controllers set to `ENGINE`. A new Arena coordinator routes each typed runtime search effect to the engine gateway assigned to the authoritative side to move; Slot A and Slot B remain isolated and neither can mutate game state. Arena UI observes immutable state. UCI rank-one score updates cross the existing typed Binder boundary as correlated presentation data and never enter legality or runtime mutation. Arena-specific setup, restore metadata, and opening fixtures remain in the app layer; the later M24 reusable import/editor/saved-position subsystem is not pulled forward.

**Authoritative sources:** `docs/implementation/IMPLEMENTATION-PLAN.md` M20; `docs/design/LumenChess-Full-Design-Spec.md` §§7–8, 10.4–10.5; `docs/design/DECISIONS.md`; `docs/design/UI-FLOWS.md`; ADRs 0001, 0004, 0009, 0011–0013, 0016–0017; P5/P6 checkpoints.

**Scope boundary:** M20 includes Arena setup/start/live/end, independent engine/strength/model/color assignment, clocks, Standard/Chess960, Normal/Random Opening/Opening Family/Custom FEN/Random Chess960 starts, canonical `ENGINE_ARENA` persistence, and default evaluation display. M21 manual opening/takeover/return, M22 branching, and M24 generalized imports/exports/editor/saved positions are explicitly excluded.
